# yanxu-http 使用指南

## 1. 添加依赖

```sh
yanbao add http --version '^1.0'
yanbao install
```

清单最低要求言序 1.1.6。应用若监听 TCP，必须在自己的`言序.toml`声明实际地址；不要因为库允许回环地址就假定生产地址已经授权。

## 2. 离线解析

`解析请求头`接收不含末尾空行、且没有正文的首部文字：

```yanxu
引「包:http」为 HTTP；

定 请求 为 HTTP.解析请求头（
    「GET /articles?page=1&page=2 HTTP/1.1\r\nHost: example.com:8080\r\nCookie: theme=dark」
）；

言 请求.主机值（）；
言 请求.端口值（）；
言 请求.路径段（）；
言 请求.查询全部（「page」）；
```

有正文时使用`解析请求（首部，正文字节）`。声明长度必须和实际字节完全相同。离线分块输入使用`解析分块请求消息`；返回值同时包含解析后的请求、消费字节数和未消费后缀，适合协议测试。

## 3. 自定义预算

```yanxu
定 限制 为 HTTP.限制（）
    .设读取（3000，4096，32768，1048576）
    .设首部项（64，8192，32）
    .设分块（512，1024）
    .设Multipart为（32，4096）
    .设会话（50）
    .验证（）；
```

四个`设读取`参数依次是超时、最大请求行、最大首部区和最大正文。限制只可在公开硬上限内收紧或选择合适值，非法数值会立即报稳定错误。

## 4. 表单与上传

```yanxu
定 表单 为 请求.表单（）；
定 标签列 为 表单【「tag」】；

定 多部 为 请求.Multipart（）；
定 标题：文? 为 多部.字段值（「title」）；
定 文件 为 多部.文件列（「file」）【0】；
言 文件.安全文件名（）；
言 文件.大小（）；
```

URL 编码表单总是把每个名称映射到值列。Multipart 保留项顺序、重复字段、每项首部和原始文件字节。解析器不写磁盘；应用必须校验媒体类型、文件内容和业务大小，并用自己生成的名称保存。

## 5. 构造响应

```yanxu
定 响应 为 HTTP.文字响应（「ok」）
    .设首部（「cache-control」，「no-store」）
    .添Cookie（
        HTTP.Cookie（「session」，「opaque-value」）
            .设路径（「/」）
            .设安全（真）
            .设仅HTTP（真）
            .设同站（「Lax」）
    ）；
```

响应工厂包括`字节响应`、`文字响应`、`HTML响应`、`JSON响应`、`言据响应`、`状态响应`与`重定向响应`。`HTML响应`不做转义；只传入已经由安全 HTML 构建器生成的内容。`言据响应`只设置媒体类型，正文必须先由`yanju`规范序列化。

响应编码器独占`Content-Length`、`Transfer-Encoding`、`Connection`和`Set-Cookie`。定长是默认模式；`.设分块（16384）`选择分块响应，`.设关闭连接（真）`要求会话在本响应后关闭。

## 6. 持久连接

```yanxu
定 会话 为 HTTP.连接会话为（连接，限制）；

试 则
    当 真 则
        定 请求：HTTP.HTTP请求? 为 会话.读取下一请求（）；
        若 （请求 是 空） 则
            断；
        终

        若 （请求.路径 等于 「/events」） 则
            会话.发送临时响应（请求，HTTP.HTTP响应（103，字节.从文字（「」）））；
        终

        会话.发送响应（请求，HTTP.JSON响应（{「ok」：真}））；

        若 非 会话.可复用（） 则
            断；
        终
    终
救 所误 则
    定 详情 为 HTTP.错误详情（所误）；
    言 详情【「代码」】；
终

会话.关闭（）；
```

一个会话顺序处理请求。应用可在读取下一条之前响应当前请求，也可让客户端流水线多个请求；库会保留超前字节并强制响应顺序。达到会话请求预算、请求要求关闭、响应要求关闭或对端结束后，`可复用`为假。

`读取请求（）`在对端提前结束时报告错误；服务器循环通常使用`读取下一请求（）`，它在请求之间的干净 EOF 返回`空`。

## 7. WebSocket 升级

```yanxu
定 握手 为 请求.WebSocket握手（）
    .要求来源（【「https://app.example」】）；

定 子协议：文? 为 握手.选择协议（【「chat.v2」，「chat.v1」】）；
定 通道 为 会话.升级WebSocket为（请求，子协议，5000）；

定 所读：典 为 通道.接收字节（4096）；
通道.发送字节（所读【「数据」】）；
通道.关闭（）；
```

服务器偏好顺序决定子协议；不能选择客户端未提供的值。无 Origin 的非浏览器客户端不会自动获准，若应用要求 Origin，必须调用`要求来源`。扩展首部通过`扩展原文`暴露，但 1.0 不协商或实现扩展。

升级后旧`HTTP连接`只可查询状态，不能继续读写或关闭；`HTTP升级通道`拥有套接字和握手后已经读入的字节。通道不解析 WebSocket 帧。

## 8. 路由适配

`请求.路由视图（）`返回方法、规范 Host、端口、原始路径、原始查询、路径段、安全/幂等性质和关闭语义的快照。上层路由器应消费该稳定视图，并把路由参数保存在自己的请求上下文中，不要修改协议对象内部典。

## 9. 错误响应

完整请求还没解析成功时，连接边界通常不再可信；可以在安全情况下发送一个 400/413/431 响应，然后关闭连接。WebSocket 版本不为 13 时可发送`WebSocket版本响应（）`得到带`Sec-WebSocket-Version: 13`的 426。应用缺陷导致的响应编码错误不应伪装成客户端错误。

稳定错误族见 [ERRORS.md](ERRORS.md)，协议威胁与部署边界见 [SECURITY_MODEL.md](SECURITY_MODEL.md)。
