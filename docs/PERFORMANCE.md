# 性能与资源预算

## 默认预算

| 项目 | 默认或硬上限 |
| --- | --- |
| 超时 | 5000 ms |
| 请求行 | 8192 字节 |
| 首部区 | 65536 字节、最多 128 项 |
| 正文 | 4194304 字节 |
| 分块 | 最多 4096 项，大小行最多 4096 字节 |
| 尾部 | 16384 字节、最多 64 项 |
| Multipart | 最多 256 项，单项首部最多 16384 字节 |
| 每连接请求 | 默认 100，硬上限 4096 |

使用`HTTP.限制（）`创建独立配置，再通过`设读取`、`设首部项`、`设分块`、`设Multipart为`和`设会话`收紧。配置对象在创建连接会话时复制，后续修改不会隐式改变正在运行的会话。

## 内存模型

1. 请求首部先进入有界会话缓冲；超前读取的下一请求字节留在同一缓冲。
2. 定长与分块正文当前都在内存中形成一个`字节串`。
3. Multipart 在正文内存上建立项对象，并复制公开快照；它不是流式上传器。
4. 响应编码在发送前形成完整字节串；分块响应减少 framing 歧义，但不是应用级流式背压接口。
5. WebSocket 升级不复制套接字；只转移已有前缀字节和所有权。

因此应根据并发连接数收紧单请求预算。大文件上传、下载和真正流式应用需要上层专用实现。

## 可执行负载

`benchmarks/解析负载.yx`重复解析普通请求和分块正文，并验证每次结果。它是回归负载，不声称跨机器可比较的吞吐数值：

```sh
yanxu benchmarks/解析负载.yx
yanxu 字节 benchmarks/解析负载.yx
yanxu 兼容 benchmarks --json
```

性能变更应记录工具链、提交、系统、CPU 和运行轮数，分别报告树解释器与 VM；不能只保留最快一次。
