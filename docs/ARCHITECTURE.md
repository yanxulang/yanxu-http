# 架构

## 分层

`src/言序HTTP.yx`是唯一默认公开入口，负责公共类型、稳定错误、请求/响应状态机和套接字会话。四个同目录内核模块保持实现职责清晰：

- `表单内核.yx`：百分号解码、媒体类型、URL 编码表单与 Multipart 边界扫描；
- `Cookie内核.yx`：请求 Cookie 和 Set-Cookie 的语法、前缀与属性不变量；
- `路由内核.yx`：Host 授权区、路径段、方法分类与不可变路由视图；
- `WebSocket内核.yx`：版本 13 握手验证、SHA-1/Base64 接受值与子协议词法。

这些内核是包内实现，不应被消费者直接导入。

## 数据流

```text
TCP 字节
  → HTTP连接有界缓冲
  → 请求行与首部解析
  → 定长或分块正文解析
  → HTTP请求
  → 应用处理
  → HTTP响应编码
  → 同一 TCP 连接或显式关闭
```

`HTTP连接`串行维护请求数、响应数、超前缓冲、复用和关闭状态。一次只能响应当前最早的待处理请求；临时响应不推进响应计数。WebSocket 升级要求正好一个待响应请求，发送 101 后把套接字和超前缓冲一起移交给`HTTP升级通道`，旧 HTTP 所有者不能再读、写或关闭该套接字。

## 不变量

1. 首部与正文 framing 在应用看到请求前确定，`Content-Length`与`Transfer-Encoding`不能并存。
2. 所有分配和循环都受`HTTP限制`或固定上限约束。
3. 请求保留重复普通首部，同时对 Host、长度、版本和升级关键首部执行唯一性规则。
4. 响应编码器拥有长度、传输编码、连接和 Set-Cookie 输出，调用方不能注入冲突 framing。
5. 普通响应编码器拒绝 101，防止绕过升级所有权转移。
6. 错误的程序接口是稳定代码，不是展示消息。

## 扩展边界

上层路由使用`HTTP请求.路由视图（）`和 Host/路径/方法助手，不需要依赖解析器内部典结构。完整 Web 框架应在`yanxu-web`中组合路由、中间件和内容协商；客户端职责属于`yanxu-request`，避免服务端库形成循环依赖。
