# 从 0.1 迁移到 1.0

1.0 保留主要请求/响应工厂，但把协议边界从“一连接一请求”扩展为严格的 HTTP/1.1 会话。建议按以下顺序迁移。

## 1. 更新依赖和工具链

```sh
yanbao add http --version '^1.0'
yanbao update
```

最低言序从 1.1.5 提升到 1.1.6。重新生成并提交应用的`言序.lock`。

## 2. 选择连接模型

旧的`读取请求（套接字）`与`发送响应（套接字，响应）`仍适合明确的一次请求连接，并保持关闭语义。要支持 keep-alive、分块请求、流水线或 WebSocket，改为：

```yanxu
定 会话 为 HTTP.连接会话为（连接，HTTP.限制（）.设会话（100））；
定 请求 为 会话.读取请求（）；
会话.发送响应（请求，响应）；
```

必须把同一个`HTTP请求`传给响应方法，以便正确处理 HEAD、连接复用和响应顺序。不要在升级后继续使用或关闭旧会话。

## 3. 接受更严格的拒绝规则

- HTTP/1.1 请求必须有一个有效 Host；
- 冲突`Content-Length`/`Transfer-Encoding`、逗号长度、重复 Host 与走私输入会稳定失败；
- Cookie、查询、首部、尾部、Multipart 和 WebSocket 关键字段都有数量与字节上限；
- 失败代码统一为`YANXUN_*`，使用`错误详情`判断，不解析错误消息。

如果旧应用依赖宽松输入，应修复调用方或代理，不要在边界前做含糊重写。

## 4. 表单和文件

对 URL 编码正文调用`请求.表单（）`；对 Multipart 调用`请求.Multipart（）`。重复值保留为列，文件内容保持字节。`安全文件名（）`只移除路径语义，应用仍应生成自己的存储名并限制总磁盘占用。

## 5. 响应与 Cookie

普通`响应.编码（）`仍产生关闭连接的定长响应。会话内部改用`编码为（请求方法，保持连接）`，并可选择`设分块（块字节数）`。禁止调用方设置`Content-Length`、`Transfer-Encoding`、`Connection`或`Set-Cookie`普通首部。

Cookie 默认`Path=/`、`HttpOnly`、`SameSite=Lax`。`SameSite=None`和`Partitioned`要求`Secure`；安全前缀也会严格验证。删除 Cookie 使用`删除（）`，它设置明确过期语义。

## 6. WebSocket

先检查 Origin 和子协议，再由会话升级：

```yanxu
定 握手 为 请求.WebSocket握手（）.要求来源（【「https://example.com」】）；
定 子协议：文? 为 握手.选择协议（【「chat」】）；
定 通道 为 会话.升级WebSocket为（请求，子协议，5000）；
```

版本不是 13 时可返回`WebSocket版本响应（）`。不要通过普通`HTTP响应（101，……）`绕过升级；1.0 会以`YANXUN_UPGRADE_REQUIRED`拒绝。升级通道是原始字节通道，帧协议由调用方实现。

## 7. 验证迁移

运行静态检查、全部规格、树/VM 对照、真实 TCP 集成和发布构建。重点回归代理输入、最大正文、流水线、错误后关闭、Cookie 前缀和升级后所有权。
